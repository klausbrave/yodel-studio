# Yodel Studio analytics

Collection starts with the analytics deployment on 9 November 2026. It does not recover earlier visits.

## Website traffic

In Cloudflare, choose **HackHumanity → Analytics & Logs → Web Analytics**, then `yodel-studio.hackhumanity.workers.dev`. This shows visits, pageviews, referrers, countries, browsers/devices and page performance. A visit is not a uniquely identified person. See [Cloudflare's definitions](https://developers.cloudflare.com/web-analytics/data-metrics/high-level-metrics/).

## Instrument usage

The `yodel_studio_usage` Analytics Engine dataset records:

| Event | When it is counted |
| --- | --- |
| `play` | The audio engine reports that playback has started; includes resuming after a pause. |
| `remix_created` | A named copy is created, or editing a shared song creates a local remix. Renames are excluded. |
| `share_created` | A playable share link has been successfully generated. Opening a failed share dialog is excluded. |
| `share_copied` | The browser confirms the link was written to the clipboard. Manual copying cannot be verified. |
| `shared_open` | A shared song has been decoded and opened successfully. Invalid links are excluded. |
| `engagement` | Seconds with the tab visible; collected every 30 seconds, on actions, and when the page is hidden or closed. |

`blob1` is the event name. `double1` is the batched action count (visible seconds for `engagement`); `double2` is 1 only for the first occurrence of that event in the current page visit. Engagement records an initial zero so short visits are included in the average. `index1` is a fresh random sampling key per batch, generated by the Worker. It is not a user or session identifier. IP addresses are used transiently for rate limiting, not written to this dataset.

Use the authenticated [Analytics Engine SQL API](https://developers.cloudflare.com/analytics/analytics-engine/sql-api/) with account **Account Analytics: Read** permission. The connected Cloudflare tool can run the same queries. Reporting is not exposed by the public app.

Actions and visits using each feature over the last seven days:

```sql
SELECT blob1 AS event,
       SUM(_sample_interval * double1) AS actions,
       SUM(_sample_interval * double2) AS visits_using_feature
FROM yodel_studio_usage
WHERE timestamp >= NOW() - INTERVAL '7' DAY
  AND blob1 != 'engagement'
GROUP BY event
ORDER BY actions DESC
```

Daily usage (UTC):

```sql
SELECT toDate(timestamp) AS day, blob1 AS event,
       SUM(_sample_interval * double1) AS actions,
       SUM(_sample_interval * double2) AS visits_using_feature
FROM yodel_studio_usage
WHERE timestamp >= NOW() - INTERVAL '30' DAY
  AND blob1 != 'engagement'
GROUP BY day, event
ORDER BY day, event
```

Average visible time per measured page visit, in seconds:

```sql
SELECT SUM(_sample_interval * double1) AS visible_seconds,
       SUM(_sample_interval * double2) AS measured_visits,
       SUM(_sample_interval * double1) / SUM(_sample_interval * double2) AS average_visible_seconds
FROM yodel_studio_usage
WHERE timestamp >= NOW() - INTERVAL '7' DAY
  AND blob1 = 'engagement'
```

The time metric counts a visible tab, not proof someone is paying attention. Background time is excluded. Sleep or a suspended browser can delay the final update, and the last heartbeat may be lost. These are best-effort counts, not a count of distinct human beings. Do not add the feature-visit columns together: the same visit can play, remix and share. Query results may be sampled at high volume, which is why queries apply `_sample_interval`.

## Cost and development

Web Analytics is free. Each application-event batch uses one Worker invocation and writes at most six Analytics Engine data points. An idle visible tab sends a heartbeat every 30 seconds; a background tab sends none. Static assets do not invoke the event Worker. As of 9 November 2026, Cloudflare says Analytics Engine is not yet billed and documents a Free allowance of 100,000 writes/day and 10,000 queries/day; Worker requests have separate account-wide limits. Recheck [Analytics Engine pricing](https://developers.cloudflare.com/analytics/analytics-engine/pricing/) and [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) when estimating future usage.

Run `bun run typecheck`, `bun test tests/analytics-worker.test.js`, and the existing browser checks before deploying. With the Vite preview running, `YODEL_URL=http://127.0.0.1:5343/ bun run test:analytics` verifies the real UI events, background-time exclusion, redaction, and continued playback when analytics is blocked. It routes the production hostname to the local build and intercepts analytics posts, so tests do not add live data. `bun run preview:worker` tests asset routing and the endpoint in Cloudflare's local runtime. Localhost itself does not emit browser analytics.
